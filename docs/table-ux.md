# 카드 테이블 입력 관례와 적용

조사일: 2026-09-19. 모드: Reference — 현행 공식 조작 설명을 읽고 로컬 테이블에 적용했다.

## 판단

직접 드래그와 F 뒤집기, 상태 변경과 확대의 분리는 여러 가상 테이블에 반복되는 관례(de-facto)다. 반면 **모든 키가 통일된 단일 표준은 없다**. 정확한 Space·섞기 키 배치는 contested이며, 이 조사만으로 최근 하나의 방식으로 이동하는 추세나 frontier는 주장하지 않는다.

로컬 제품은 규칙을 강제하지 않는 브라우저 2D 테이블이다. 구현 형태가 같은 Screentop이 close, 3D 카메라·물리·손패 영역을 가진 Tabletop Simulator와 Tabletopia는 adjacent다. 물리 시뮬레이션·카메라 조작은 가져오지 않고 선택·이동·확대·맥락 메뉴의 조작 관례만 비교했다.

최초에는 클릭을 선택으로만 사용했다. 후속 사용자 승인에 따라 **뒷면 클릭은 펼쳐 가져오기**, **1/2/3은 한 장 획득 또는 2/3장 중 선택**으로 바꿨다. 선택만 할 때는 Shift+클릭이나 덱 이름을 사용한다. 이는 이 워크벤치의 로컬 동작 계약이며 업계 공통 표준이라는 주장은 아니다.

## 근거와 적용

| 근거 | 실제로 확인한 것 | 적용 / 차이 |
| --- | --- | --- |
| [TTS 기본 조작](https://kb.tabletopsimulator.com/player-guides/basic-controls/) | 드래그, F 뒤집기, Alt 확대, 박스 선택, 우클릭 메뉴. Space는 카메라 복귀 | F·Alt·직접 조작 채택. 카메라용 Space 의미는 채택하지 않음 |

| [Tabletopia 오브젝트 조작](https://help.tabletopia.com/knowledge-base/actions-with-game-objects/) | 먼저 선택한 덱은 전체 드래그, F, 우클릭 메뉴, Shift 선택, 강조된 대상에 쌓기 | 선택 전 한 장 / 선택 후 덱 전체 드래그, 드롭 대상 강조. 원형 메뉴 모양은 복제하지 않음 |

Screentop 원문은 [공식 Learn 페이지](https://screentop.gg/learn/controls-and-shortcuts)가 불러오는 문서다. TTS 문서들은 한 제품의 근거로 묶었으며 독립 신호 여러 개로 세지 않았다. 서로 독립인 세 제품에서도 확대·섞기 키는 다르므로 하나를 “업계 전체 표준”이라고 부르지 않는다. 다른 2D 제품과 실제 사용자 관찰에서 반대 패턴이 반복된다면 이 적용 판단을 재검토해야 한다.

## 로컬 동작 계약

- 뒷면 클릭/1은 위 한 장을 앞면 손패로 가져와 확대한다. 앞면 클릭·덱 이름 클릭은 선택이다. 선택하지 않은 덱의 드래그는 위 한 장, 선택한 덱의 드래그는 전체다. Shift+클릭 또는 빈 곳 드래그로 다중 선택한다.
- 앞면 더블클릭은 고정 확대, Space/Alt는 누르는 동안 현재 면 확대다. 숨겨진 제목·본문·태그는 뒷면 DOM과 접근성 이름에 넣지 않는다. 펼쳐 고르는 후보는 의도적으로 앞면을 표시한다. 이는 로컬 표시이며 접근 권한 보장은 아니다.
- F는 묶음 전체를 실제로 뒤집듯 순서를 뒤집고 각 면을 반전한다. 두 번 하면 원래 상태다. R은 순서를 섞고 카드별 앞뒤는 보존한다.
- 2/3은 맨 위에서 해당 장수만큼 앞면 후보를 보여준다. 클릭한 한 장만 앞면 손패로 가져오고, 나머지 후보는 원래 순서를 유지한 뒷면으로 남는다. 부족하면 남은 카드만 사용한다. 취소는 상태 변경 없이 닫고, 확정은 기록 하나로 남긴다. 새 손패 카드가 선택되어 후속 이동·F 등에 이어진다. G는 마지막 선택 위에 쌓는다.
- 손패는 아래쪽 좌표에 놓인 카드이며 독립 소유권 모델은 없다. 모든 표면에서 2:3 비율과 전체 본문을 유지한다. 카드 내부·확대·선택은 무스크롤, 라이브러리 목록 스크롤은 허용한다.
- 조작은 마우스로 가리킨 대상, 키보드 초점, 선택 순서로 결정한다. 가리킨 대상이 선택에 포함되면 함께 적용한다. 확대는 그중 가리킨/초점 카드 한 장만 읽는다.
- 드래그는 미리보기만 바꾸다가 놓을 때 기록 하나로 확정한다. Esc·pointer cancel·창 포커스 이탈은 미완료 입력을 취소한다.
- 입력 필드·contenteditable·IME 조합·다른 대화상자에는 테이블 단축키가 개입하지 않는다. Ctrl/⌘+F·R 등 브라우저 조합키는 보존한다.
- 우클릭 메뉴는 키보드로 접근하고 닫으면 대상에 초점을 돌려준다. 상단 동작 버튼과 조작법은 보조 진입점이며 영구 사이드바는 추가하지 않는다.

## 검증 범위

- 도메인: 카드 수·순서·앞뒤 보존, 전체 뒤집기 왕복, 후보 비파괴 조회, 한 장 선택·미선택 뒷면 복귀, 마지막 카드·잘못된 선택, 꺼내기·쌓기·경계 이동.
- 입력 이벤트: 클릭/더블클릭, Space/Alt 유지·해제, 포커스 이탈, IME·반복 키 차단, 드래그 중 취소와 단일 확정, 새 선택으로 후속 조작, 메뉴 초점 복귀.
- 연결된 Chrome: 한 장 드래그와 덱 전체 이동, 직접 쌓기, 단축키 뒤집기·섞기·꺼내기·쌓기, 다중/박스 선택, 우클릭/Shift+F10, 확대·닫기, 되돌리기·다시 하기, 입력 필드 회귀.
- Chrome 도구는 키다운/키업을 분리해 유지하는 입력을 지원하지 않았다. Space/Alt가 유지되는 중간 상태와 드래그 도중 Esc/blur는 DOM 이벤트 테스트로 보완했으며 실제 지속 입력을 자동 검증했다고 주장하지 않는다. jsdom의 native dialog top-layer는 모사하고 실제 대화상자는 Chrome에서 검증한다.
- 후속 Chrome 검증: 클릭/1 획득, 3장 중 선택, 미선택 뒷면 복귀, 2장 선택 취소, 획득 한 번의 되돌리기·다시 하기. 1280×720과 1440×900에서 카드 2:3·본문 넘침 없음·선택/확대 창의 화면 내 배치를 확인한다.
